# RFC-021 Acceptance / QA Checklist

**A checked box means evidence exists.** A requirement that could not be met stays unchecked with a stated reason in `qa-evidence.md`.

## Channel Checklist

- [ ] Approval channel is a Unix domain socket, never the PTY stream.
- [ ] Endpoint lives under the state root, outside every project root.
- [ ] Path validation rejects symlink redirection, matching RFC-011/RFC-013 discipline.
- [ ] One endpoint per AgentRun; destroyed on termination.
- [ ] Socket permissions restricted to the owning user.
- [ ] Per-run capability token generated by Tekstide.
- [ ] Token delivered through the environment allowlist only.
- [ ] Token never persisted to disk unencrypted.
- [ ] Token never appears in a durable audit record.
- [ ] **A non-adapter process cannot submit a proposal.**
- [ ] **A non-adapter process cannot submit a decision.**
- [ ] A token from another AgentRun is rejected.

## Protocol Checklist

- [ ] `CommandProposal` supplies argv as a vector; shell strings rejected.
- [ ] Unknown protocol version rejected without negotiation.
- [ ] Malformed messages rejected; no partial parse.
- [ ] Oversized fields rejected.
- [ ] Duplicate proposal id rejected.
- [ ] Adapter-declared effects never lower risk or skip approval.
- [ ] All diagnostics bounded and content-free.

## Risk Classifier Checklist

- [ ] Path outside canonical project root escalates to at least `High`.
- [ ] Privilege elevation escalates.
- [ ] Git remote-mutating operations escalate.
- [ ] Secret-like path patterns escalate.
- [ ] Writes to the Tekstide state root escalate.
- [ ] Recursive deletion / disk operations / history rewriting classify `Destructive`.
- [ ] **Unclassifiable input classifies `High`, never `Low`.**
- [ ] Fixture corpus covers both directions — escalating and ordinary.
- [ ] No shell-grammar interpretation.

## Decision Checklist

- [ ] Every adapter-submitted proposal requires an explicit decision.
- [ ] No risk threshold executes silently.
- [ ] Decisions are single-use and bound to one proposal id.
- [ ] `ApprovalRequest` append-only transition from `Pending` preserved.
- [ ] Edit-and-approve re-runs risk classification on the edited argv.
- [ ] Audit describes what was approved, not what was proposed.
- [ ] Rejected proposals never execute.

## Fail-Closed Checklist

- [ ] No response → pending indefinitely; **no timeout approves**.
- [ ] Adapter disconnect while pending → abandoned, no execution.
- [ ] AgentRun termination while pending → abandoned, no execution.
- [ ] Audit append failure for authorization → execution blocked.
- [ ] Invalid or absent token → rejected without a dialog.

## Audit Checklist

- [ ] Events conform to the frozen `command_approval` family; schema unamended.
- [ ] `command_request` / `command_approve` / `command_edit_and_approve` / `command_reject` used per the mapping.
- [ ] One operation id per approval; authorization precedes execution.
- [ ] `approval_id` and `risk_level` present; `terminal_id` and `subject_kind` absent.
- [ ] Written via `AuditCoordinator`, not directly to the store.
- [ ] **Sentinel test: no command text, argv, cwd, or intent text in the durable store.**

## Scope Boundary Checklist

- [ ] `Plain` runs expose no approval path.
- [ ] `Supervised` runs expose no approval path.
- [ ] `Managed` still requires proven adapter capability per RFC-010.
- [ ] No pattern-based or always-allow rules implemented.
- [ ] No rendered dialog implemented — decision API only.
- [ ] No OS-level interception.

## Honesty Checklist

- [ ] Documentation states approval is cooperative, not enforced.
- [ ] No code path or message implies Tekstide approves commands generally.
- [ ] Closeout records exactly what may be claimed about approval.

## Evidence Required

- [ ] Commit/PR list.
- [ ] Gate command output.
- [ ] Risk classifier fixture corpus.
- [ ] Impersonation test results.
- [ ] Audit conformance and sentinel-privacy test results.
- [ ] Known limitations.
- [ ] Answers to the RFC's open questions.

## Final Acceptance Decision

- [ ] Accepted.
- [ ] Accepted with required follow-up.
- [ ] Requires re-review after changes.
- [ ] Blocked — channel cannot be made impersonation-resistant.
